# Thirukkural Website — Content & Explanation Workflow

## 1. Core Principle

The website must separate **verified Thirukkural content** from **AI-generated engagement content**.

### Verified content

This must never be generated by AI:

* Kural number
* Original Tamil Kural
* Transliteration
* Paal
* Iyal
* Adhigaram
* Tamil meaning
* English meaning
* Basic explanation
* Search keywords
* Themes

### Generated content

This can be generated dynamically:

* Engaging explanation
* Modern-life example
* Story/narrative
* Practical application
* Reflection question
* Memorable takeaway

The original Kural must always come from the verified dataset.

# 4. Why `themes` and `lifeApplications` matter

These fields allow the website to become more intelligent without requiring a huge explanation for every Kural.

For example:

```json
"themes": [
  "education",
  "wisdom",
  "humility"
],

"lifeApplications": [
  "learning",
  "career",
  "personal growth"
]
```

The website can then show:

```text
Themes

📚 Education
🧠 Wisdom
🙏 Humility

Useful in

Learning
Career
Personal Growth
```

These can also be used for search and recommendations.

# 6. Explain Button

The Explain button is the main interactive feature.

When the user clicks:

```text
[ Explain This Kural ]
```

the system should send the verified information to the AI.

The AI receives:

```text
Kural number
Original Tamil Kural
Tamil meaning
English meaning
Simple explanation
Themes
Life applications
Language requested
```

It should NOT be asked to recreate or verify the original Kural.

---

# 7. AI Explanation Prompt

Use a fixed system prompt rather than allowing the user to control the explanation format.

Conceptually:

```text
You are a Thirukkural explanation assistant.

The original Kural provided to you is authoritative.
Never modify, rewrite, or invent the Kural.

Your task is to help a modern reader understand its wisdom.

Create an engaging explanation using this structure:

1. Hook
2. Real-life situation
3. Connection to the Kural
4. Deeper meaning
5. Modern application
6. Memorable takeaway

The explanation should feel like a compelling story,
not like a textbook.

Use emotional tension, curiosity, and a satisfying realization.

Do not imitate any specific anime, movie, author,
character, or copyrighted work.

Keep the explanation faithful to the supplied meaning.

Do not invent historical facts about Thiruvalluvar.

Language: Tamil/English depending on the user's selection.
```

# 9. Do NOT make every explanation the same length

This is important.

Do not force every Kural into:

```text
500-word story
```

Instead use three explanation levels.

### Level 1 — Understand

Always available.

```text
2–4 sentences
```

Comes from your JSON.

### Level 2 — Apply

Generated or stored.

```text
Modern-life application
```

Example:

```text
How does this apply to students?

How does this apply to relationships?

How does this apply to work?
```

### Level 3 — Explore

Optional AI narrative.

```text
🎭 Story
💭 Deeper interpretation
🌱 Life lesson
```

This keeps the website lightweight while giving users depth when they want it.

# 10. AI Generation Strategy

Do NOT generate explanations for all 1,330 Kurals when building the website.

Instead:

```text
User opens Kural 500
        ↓
Reads verified content
        ↓
Clicks "Explain"
        ↓
Check cached explanation
        ↓
    ┌───┴───┐
    │       │
  Exists   Doesn't exist
    │       │
    ▼       ▼
 Return    AI
            │
            ▼
         Generate
            │
            ▼
           Save
            │
            ▼
          Return
```

This dramatically reduces unnecessary AI usage.

# 11. Cache AI explanations

Eventually store generated explanations separately from the main Kural dataset.

For example:

```text
data/
│
├── kurals.json
│
└── explanations/
    ├── 1.json
    ├── 2.json
    ├── 3.json
    └── ...
```

An explanation file could look like:

```json
{
  "kuralId": 2,
  "language": "en",
  "version": 1,

  "hook": "...",

  "story": "...",

  "modernApplication": "...",

  "takeaway": "..."
}
```

This means your authoritative dataset stays clean.

# 12. Language Handling

The user selects:

```text
தமிழ் | English
```

The website should use the selected language throughout the interface.

For example:

### Tamil

```text
குறளை விளக்குக
```

### English

```text
Explain this Kural
```

When generating AI explanations, explicitly send:

```text
language = Tamil
```

or:

```text
language = English
```

Do not translate the original Kural using AI.

# 19. AI Backend — V1

Do not expose an AI API key directly in the browser.

If the Explain feature requires an external LLM API, introduce a small server-side API layer.

For example:

```text
React
   ↓
/api/explain
   ↓
LLM API
```

This can initially be a simple serverless/API endpoint.

You do NOT need a complete FastAPI + database architecture just for this.

# 21. Most Important Rule

Never allow AI to become the source of truth for the Thirukkural.

```text
                  SOURCE OF TRUTH
                         │
                         ▼
                Verified Kural JSON
                         │
            ┌────────────┴────────────┐
            ▼                         ▼
       Website display            AI context
                                      │
                                      ▼
                              Generated explanation
```

AI explains the wisdom.

AI does not define the Kural.

# 22. Final Content Strategy

For all 1,330 Kurals:

### Required

```text
✓ Original Kural
✓ Transliteration
✓ Tamil meaning
✓ English meaning
✓ Simple explanation
✓ Themes
✓ Life applications
✓ Search keywords
```

### Optional / Generated

```text
○ Modern example
○ Story
○ Deeper explanation
○ Reflection
○ Takeaway
```

This gives you the best balance:

**1,330 Kurals × small verified dataset**

instead of:

**1,330 Kurals × huge manually written narratives**

# Final Product Philosophy

The website should not simply answer:

> "What is Kural 847?"

It should help the user go through:

> **"What does Kural 847 say?"**

↓

> **"What does it mean?"**

↓

> **"Why did Valluvar say this?"**

↓

> **"Where do I see this in my life?"**

↓

> **"How can I apply it?"**

↓

> **"I want to read another one."**

That is the core experience the entire UI, data model, search, recommendation system, and Explain feature should be designed around.
